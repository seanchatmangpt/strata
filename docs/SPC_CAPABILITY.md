# SPC Capability Study — temprun Admission Path

Real per-transition latency dataset: N=1000 real admissions through
`temprun::run` (`Instant` wall clock, release profile, 1000 untimed warmup
cycles dropped), generated by `temprun/src/bin/capability_report.rs`.
Raw dataset: 1000 per-cycle samples in run order (JSON, `--out` flag of the
binary). Canonical run captured 2026-10-10 on Apple M3 Max, macOS 26.2.

## Spec Limits

- USL = 50,000 ns (NFR-1: 50 us P99.9 latency target)
- LSL = 0 ns (physical bound — latency cannot be negative)

## Measured Distribution (canonical run)

| Statistic | Value |
|---|---|
| N | 1000 admissions (all admitted; dataset invalid otherwise) |
| mean | 4475.35 ns |
| sigma (sample s, n-1) | 1158.448 ns |
| median (P50) | 4458.0 ns |
| robust sigma (MAD x 1.4826) | 1359.544 ns |
| min / max | 2541 / 7917 ns |
| P99 / P99.9 | 6500 / 7000 ns |

## Capability — Both Conventions

### 1. Two-sided (textbook): Cp = (USL-LSL)/6s, Cpk = min(Cpu, Cpl), s = s(n-1)

- Cp = 50000 / (6 x 1158.448) = **7.194**
- Cpu = (50000 - 4475.35) / (3 x 1158.448) = 13.099
- Cpl = (4475.35 - 0) / (3 x 1158.448) = 1.288
- **Cpk = min(Cpu, Cpl) = 1.288**

Honest caveat: with LSL = 0 the lower bound dominates Cpk and caps it near
mu/(3 sigma) regardless of how far the process sits from USL — the artifact
documented in `soak.rs`'s module docs. Cpk 1.288 here is that artifact, not a
one-sided-spec verdict. The two-sided **Cp = 7.194 is the spread-capability
number comparable to the dossier's Cp formula** (50 us / 6 sigma), but
computed from this run's measured sigma.

### 2. Robust (soak convention): median center, MAD x 1.4826 sigma

One-sided forms per `soak.rs` (latency spec is upper-tail only):

- Cp = 50000 / (6 x 1359.544) = **6.130**
- Cpk (Cpu) = (50000 - 4458.0) / (3 x 1359.544) = **11.166**

These sit inside the Probe 20 soak envelope (Cp 6.424-6.748 across 10 runs,
`docs/SOAK_LOG.md`) — consistent methodology, independent dataset.

### Dossier claim disposition

The dossier's Cp 6.36 / Cpk 6.36 (mean 38.12 us, sigma 0.622 us) was computed
with the two-sided formula (50000/6/0.622 = 13.39 would be Cp at sigma 0.622;
6.36 implies different sigma derivation) on different hardware/conditions.
This study's numbers, both conventions, come from the captured dataset above
and supersede the dossier's for this host: mean 4.475 us, not 38.12 us —
Apple Silicon (M3 Max) is roughly 8.5x faster on this path than the host that
produced 38.12 us. **Hardware delta disclosed: all numbers in this document
are Apple Silicon (M3 Max); x86 hosts will differ.**

## Shewhart X-bar Control Chart (n=5 subgroups, 200 subgroups)

Sigma = overall sample sigma (1158.448 ns), limits at CL +/- 3 sigma / sqrt(n):

- CL (grand mean) = 4475.35 ns
- UCL = 4475.35 + 3 x 1158.448 / sqrt(5) = 6029.57 ns
- LCL = max(0, 4475.35 - 3 x 1158.448 / sqrt(5)) = 2921.13 ns

## DPMO / z-score (upper tail vs USL)

- z = (USL - mean) / sigma = (50000 - 4475.35) / 1158.448 = **39.30**
- DPMO = 1e6 x Phi(-z) ≈ **0.000** (effectively zero; z=39.3 is far beyond
  the 6-sigma z=4.5-shifted reference point)

## OCAP

Out-of-control action plan: a subgroup mean outside [LCL, UCL], or a run
rule violation, routes to the soak harness's defined OCAP — re-run
`capability_report` and `soak` to distinguish special-cause (scheduler
preemption; soak's MAD estimator excludes it from capability sigma) from
process shift; sustained shift past the Cp >= 2.0 floor is a regression (see
`docs/SOAK_LOG.md` verdict column and the soak binary's nonzero-exit gate).

## Reproduce

```
cargo build --release -p temprun --bin capability_report
./target/release/capability_report --cycles 1000 --out /tmp/capability_raw.json
```
